# The installation map as the irreducible core

Date: 2026-09-03

Record ID: `SRC-2026-09-03-INSTALLATION-MAP-AS-IRREDUCIBLE-CORE`

Status: user-attributed evidence record. It continues `SRC-2026-09-03-CORE-PURPOSE-AND-INSTALLATION-MAP` and states which part of the accumulated design is irreducible and what that implies.

## The user's words, verbatim

> 是……我确实在一开始给它添加了许多设定和想法，并且想要渐渐地拓展它的功能——尝试让它不仅能创建，也能参与维护，而后者才是真正重要的
> 但是剥离所有外壳后，不可剥离的核心就是安装地图的比喻——既然是安装地图，那么所有功能都应当能被触及，这自然形成了奥卡姆剃刀的作用

## What this decides

1. Provenance of the accumulated material. Many of the settings and ideas in this package were added at the start as deliberate extension attempts. They are the shell, not the core, and the user says so directly.
2. Priority within `IP-0`. Creating a project is the entry; participating in its continued maintenance is what actually matters. Extension work is aimed at the maintenance half.
3. The irreducible core is the installation-map metaphor. Everything else can be stripped away and the project remains itself.
4. The razor. Because it is a map, every capability must be reachable by following it. Reachability is the criterion, and it acts as Occam's razor on its own: material the map never has to reach earns no normative standing, and a capability the map cannot reach is not delivered.

The razor is a consequence of the metaphor, not an added rule. The user derived it in one step from "it is a map", and this record preserves that derivation rather than presenting it as an independent policy.

## Scope of this record

Intent clarification with one new acceptance criterion. It ranks maintenance above creation inside the existing `IP-0` rather than replacing it, and it does not by itself retire any `IP-*` intent, existing `META-*` criterion, constraint or open tension. Applying the razor to remove specific accumulated material is a separate user decision, per capability, and no such removal is performed here.
