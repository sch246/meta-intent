A mechanical check recognizes the boundary tokens and balances them independently per package without pretending to validate the prose purpose.

## Generated composition

Both features contribute source declarations whose aggregation appears in `slot-catalog.ts` and `api-catalog.ts`. Neither package patch owns those generated paths. Their setup/uninstall procedures regenerate both catalogs from all remaining source contributions, and their Git-private receipts record the generated mapping beside exact patch provenance.

This is a concrete composition improvement over storing both packages' generated bytes in one or both static patches: removing one source contribution causes regeneration while leaving the other source contribution available to the generator.

## Authority boundary

The locator check establishes boundary balance and discoverability only. Setup still requires exact forward/reverse patch state and records whether that invocation actually owned the patch. Uninstall requires matching provenance and reverse applicability. An Agent remains responsible for interpreting the ordinary purpose comment and investigating current code, Git, state, locks, receipts, generated mapping, and drift before maintenance or removal.

## Remaining gap

The two packages currently govern disjoint semantic source regions and share only generated aggregation surfaces. The package-relative validator is designed to permit crossing boundaries (`begin A`, `begin B`, `end A`, `end B`), but an actual jointly edited source span and one-owner re-synthesis exercise remain unperformed. No test suite, live setup/uninstall, or service restart was run for this practice, per user direction.
