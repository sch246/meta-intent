## T-9: unselected log files are silent

At commit `5bc17fd612f1f0f0ff7f78e38b09a77822e167fc`, both newly added records were selected in `state/STATE.json.logs` and bound by digest in the current protocol lock. The suspected omission did not occur.

The structural tension nevertheless exists. `validatePackage` resolves only the paths selected by `state.logs`; it does not enumerate `logs/` and compare that directory with the selection. Codex copied the package to an isolated temporary directory, added an extra unselected file under `logs/`, and the package still validated. Selected provenance triggers current-lock snapshot and digest propagation; an unselected file triggers neither cost nor warning.

This creates a gradient toward accumulating files that look like package provenance but are absent from the current projection's declared sources. A later revision must decide whether unselected files are permitted archival material, require an explicit status or index, or are a topology error. This observation does not authorize selecting every file automatically.

## T-10: findings need investigator and access-scope provenance

The missing attribution above is an instance of T-5 at the report layer. A conclusion derived from public source inspection, a local target checkout, an executed probe, and a relayed review do not have the same reproducibility or applicability, even when they support one report.

A later protocol candidate should let consequential findings identify the investigator, access scope, method, and evidence pointer without forcing raw transcript retention. This is attributable provenance, not a claim that the named investigator is semantically authoritative.

## T-11: a fork has two possible identities

Protocol 0.1 section 9 describes repositories and forks as decentralized evidence and proposal channels into canonical maintenance. The user's clarification establishes a second role: a fork may instead be an exit that creates a distinct protocol and canonical center.

The two roles depend on declared intent. A proposal fork asks the existing center to consider a change; an exit fork no longer asks that center for canonical status. A later revision should express both without treating every fork as either implicit authority over the original protocol or merely a pending contribution to it.

## T-5 additional instances

Two earlier silent-scope failures were omitted from T-5:

1. Codex treated the local `/root` checkouts as available test candidates during cross-Agent reasoning before making their host-local source scope explicit. The current state now labels them `local-bootstrap`, but that later correction does not erase the original failure.
2. The relayed review records Claude assuming it lacked repository access after it had already used that access. This concerns an Agent's model of its own current capability rather than an external claim.

External claims and self-state assumptions therefore need different evidence paths. The former need source, applicability, and authority scope; the latter require checking the Agent's recent actions and current tool/environment state. Both remain investigation triggers unless a protocol supplies a sufficient predicate for the bounded conclusion.
